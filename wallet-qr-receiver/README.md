# Wallet QR Receiver (P0-5)

Mobile wallet QR code scanning and credential reception system for receiving and managing academic credentials.

## Overview

The Wallet QR Receiver enables users to:
- Scan QR codes to receive credentials
- Store credentials locally on device
- Manage multiple credentials
- View credential details and expiration
- Export and import credentials
- Access credential metadata for verification

## Architecture

```
Wallet QR Receiver:
  ├── QR Parsing (JSON, BASE64)
  ├── Credential Validation
  ├── Local Storage Management
  ├── Credential Lifecycle (receive, store, delete, export)
  └── Verification Integration
```

## Features

### QR Code Reception
- Parse QR codes containing credential metadata
- Support JSON and BASE64 encoded data
- Automatic format detection
- Validation on receipt

### Credential Storage
- In-memory credential storage
- Credential metadata preservation
- Tracking of receipt timestamps
- No sensitive claim data stored
- Efficient serialization

### Credential Management
- List all received credentials
- Filter by type, issuer, or status
- Check validity and expiration status
- Delete credentials
- Clear all credentials

### Credential Status
- **Valid**: Issued and not yet expired
- **Pending**: Issue date in future
- **Expired**: Expiry date has passed

### Import/Export
- Export credentials to JSON format
- Import credentials from external source
- Preserve metadata and timestamps
- Validation on import

### Statistics
- Total credential count
- Valid vs. expired breakdown
- Credential types distribution
- Issuer breakdown
- Storage usage

## API

### Constructor
```javascript
const wallet = new WalletQRReceiver({
  namespace: 'org.smartcollege.credential',  // Optional
  maxStorageSize: 52428800,                   // 50MB default
  autoSync: false                              // Optional
});
```

### Receive Credential
```javascript
const result = await wallet.receiveCredential(qrCodeData, options);
// Returns: { success, credentialId, metadata, receivedAt }
```

### Get Credential
```javascript
const credential = wallet.getCredential(credentialId);
// Returns: { id, metadata, receivedAt }
```

### List Credentials
```javascript
const all = wallet.listCredentials();
const filtered = wallet.listCredentials({ 
  type: 'AcademicCredential',
  issuer: 'did:key:...',
  status: 'valid' | 'expired'
});
// Returns: Array of credentials
```

### Delete Credential
```javascript
const result = wallet.deleteCredential(credentialId);
// Returns: { success, credentialId }
```

### Check Validity
```javascript
const isValid = wallet.isCredentialValid(credentialId);
const status = wallet.getCredentialStatus(credentialId);
// Returns: 'valid' | 'pending' | 'expired'
```

### Export Credentials
```javascript
const exported = wallet.exportCredentials('json');
// Returns: { success, format, data }
```

### Import Credentials
```javascript
const result = wallet.importCredentials(importData);
// Returns: { success, imported, total, errors }
```

### Statistics
```javascript
const stats = wallet.getStatistics();
// Returns: { totalCredentials, validCredentials, expiredCredentials, credentialTypes, issuers, storageUsed }
```

### Camera Scanning (Browser)
```javascript
// Start scanning
const stream = await wallet.startCameraScanning(videoElement, onQRDetected);

// Stop scanning
wallet.stopCameraScanning(stream);
```

## Credential Metadata Format

```javascript
{
  credentialId: "cred-001",           // Unique credential ID
  issuerDid: "did:key:issuer123",    // Issuer DID
  credentialType: "AcademicCredential", // Credential type
  issueDate: "2024-01-01T00:00:00Z",  // Issue timestamp
  expiryDate: "2025-01-01T00:00:00Z", // Expiry timestamp
  claimsHash: "hash123",              // Hash of credential claims
  qrCodeId: "qr-001"                  // Optional QR code identifier
}
```

## Workflow

```
1. User opens wallet app
2. Selects "Scan Credential" or camera permission granted
3. Points camera at QR code
4. System decodes and parses QR data
5. Metadata validated against schema
6. Credential stored in local wallet
7. Confirmation displayed to user
8. Credential available for verification
```

## Integration Points

### With Issuer (P0-3)
- Receives QR codes generated by issuer
- Parses credential metadata
- Displays credential details

### With Verifier Registry (P0-11)
- Uses issuerDid to look up issuer
- Verifies issuer is approved
- Validates issuer trust score

### With Signature Validation (P0-9)
- Provides credential metadata
- Facilitates verification requests
- Handles verification responses

## Security Considerations

### Data Protection
- No credential claims stored locally (metadata only)
- Credential hashes preserved for integrity
- Timestamps recorded for audit
- Storage isolation per application

### QR Code Scanning
- Validates all received metadata
- Rejects malformed or incomplete data
- Verifies issuer DID format
- Checks date consistency

### Credential Management
- Deletion is permanent
- Export contains no sensitive claims
- Import validates all credentials
- Duplicate reception prevention
